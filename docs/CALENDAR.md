# 本机时间与日历

[导航](README.md) · [使用示例](../README.md)

EventKit桥接位于`macos/AsukaLauncher.swift`，Python经项目内`.runtime/calendar-ipc`访问原桌面应用；不点击日历App。必须正常授权，拒绝/撤销/失败不能说无事件；无身份或非macOS不能伪造系统日历。查询重新读取所有已授权可读日历，单日、全天、跨日/跨年结构化列表由代码决定，模型不能省略已读事件。读取上限5000条，首批展示10条可查看更多；不完整必须显式提示。

创建：提取 → 校验 → 可写日历/疑似重复检查 → 预览 → 明确确认 → 幂等写入 → 读回。新建默认30分钟在预览标注，明确时间优先；过去/无效/DST歧义须澄清。周一为周开始，日期支持本/下/下下周星期、本/下月明确日等。未确认绝不写入，不把记忆说成已经创建/会提醒。真实创建有用户人工成功记录，当前增量日期修补主要通过隔离及有限真实Qwen/浏览器验证，不等于所有原生路径均验收。

文字修改已有实现带原身份、冲突检查、确认和读回；不删除重建，不覆盖未请求字段。`last_event`空上下文保护已部署；没有身份时明确澄清。**稳定性仍有已知问题**：上游unsupported与下游漏标题/日期是不同失败层，真实Qwen曾一轮没有预览、一轮预览成功；真实修改和原生确认按钮未验收。未通过的结构化提取/路由候选保留在原项目、没有合入公开稳定源码。仅自动模拟成功不能当成真实端到端通过。

没有删除、批量/重复日程修改、主动提醒、闹钟或通知调度；不承诺准时提醒。权限变更/签名升级可能重新弹系统提示，勿绕过。多人会议、重复实例/全天转换等修改限制由实现明确拒绝。正式私人事件必须在用户核对具体修改前后后确认；发布测试不读写私人日历。
